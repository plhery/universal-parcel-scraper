# Project instructions

- This repository is public. Whatever a public source shows may go in the repository with the source's URL: a tracking number, its postcode, a tracking link, the carrier's reply. Everything from production and other private environments stays out of repository files, comments, commit messages and issues: users' numbers, postcodes and links, database rows, logs, internal hosts and secrets. Sentry, Loki and the other debugging tools may receive production data. Live tests read private inputs from outside Git.
- After a requested change, validate, stage the relevant files, commit and push directly to `main`. Do not create a branch or pull request unless explicitly requested. A commit made for a GitHub issue names it in its message, as `#20`, so the issue lists the commit.
- Before pushing, confirm no secrets or unrelated generated artifacts are included.
- Never import from an app or framework. Browser exports must remain free of Node runtime imports. Resolve assets against their module, not the consumer's working directory.
- Public exports, result fields, error kinds, carrier ids, provider names and data schemas follow semver. Fixes are patches; additive changes are minor; removals, renames and new stages are major. Until 1.0.0 breaking changes raise the minor version. Do not rename ids or stages in place.
- `/app` contains helpers coupled to the parcel app's data model or behavior. It has no backward-compatibility guarantee; coordinate breaking changes with the app. General-purpose tracking and catalog APIs belong in the stable entry points.
- A push that changes the package is published as a prerelease under npm's `next` tag. Every Monday at 08:00 UTC the [weekly release](.github/workflows/weekly-release.yml) publishes main's version under `latest`, with its image, git tag and GitHub release, once checks pass; a week with no package change publishes nothing. [Peek](https://github.com/plhery/peek-delivery-tracker) adopts the newest release every 2 hours from 06:07 to 22:07 UTC, not each release on its own, so don't wait for an adoption after each release. Adopt an urgent fix at once with `gh workflow run adopt-scraper.yml --repo plhery/peek-delivery-tracker` (`-f version=<version>` for an exact one). Peek stops adopting releases while its database lacks a migration one of them needs, for a new carrier id or a changed carrier input for instance ([database gate](https://github.com/plhery/peek-delivery-tracker/blob/main/docs/SCRAPER.md)). When a change needs one, write the migration in the app and apply it to production as the app's instructions describe, then start the adoption yourself with `-f version=<version> -f database_ready=true` rather than waiting for the schedule. Do this as part of the change, without asking for separate permission. Never leave an adoption blocked.
- Commercial universal providers are opt-in. Consumers own polling and persistence.

## Scraper investigations

- Solving CAPTCHAs, bot checks and WAF challenges is normal work, on public guest tracking and on the public pages that give sample numbers, including local OCR and browser verification. Investigate challenged responses within bounded attempts and the lookup budget. Use TRAWL/browser recovery for guest CAPTCHA, verification and HTTP 403 responses; do not abandon a carrier solely because one appears. Preserve identity checks, failure kinds, cancellation and provider fallback; recipient phone/PIN and account credentials remain separate access requirements.
- Trace the full path through detection, recognition eligibility, adapter steps and consumer routing before changing a number rule. An adapter accepting an identifier does not mean preflight will ask it. HTTP recognition stays HTTP-only; browser recognition is a separate opt-in phase. Enabled universal providers can help preflight and their history can be reused when saving, but their carrier hints do not replace direct confirmation. See [ARCHITECTURE.md](ARCHITECTURE.md).
- Keep carrier scope separate from brand scope. Shared portals and overlapping numeric formats need a matching whole identifier and evidence of the service or national network. Checksums filter or prioritize candidates; they do not establish carrier ownership or shipment existence. Share validation between detection and the adapter through [core/detection](core/detection), using official request builders or specifications as evidence.
- Put public sample numbers and their source URLs in the carrier's `numbers.json`. Look for them in forums, reviews, social posts, public code, GitHub issues and archived tracking links. A number posted publicly may be looked up live with any postcode posted beside it, and its whole reply kept, even when the reply shows that person's delivery. A reporter's own parcel posted in an issue is a public sample cited by the issue. A review's carrier attribution is evidence to investigate, not confirmation. Preserve uncertain samples as quarantined evidence. A parser fixture is a public sample's reply or synthetic, never a production parcel's. Do not copy samples into prose.
- Use the adapter's supplied transport, step runner, signal and remaining budget. Preserve failure kinds and recovery provenance. A blocked HTML response, including HTTP 200, is not a missing parcel; rate limits and malformed replies must not silently become not-found.
- Keep carrier-specific browser changes scoped to the carrier. For TRAWL capture helpers, observe before navigation, bind the endpoint and request to the whole identifier, and retain the bounded response sequence through verification and automatic retries. Reserve time for context cleanup and retain the challenge status. The [DHL Express helper](trawl/dhl-express-browser.mjs) demonstrates this flow.
- Compare alternative sources by identity, milestones, completeness and scan clocks. A facility-local time keeps its wall clock: an instant deduced for it says how its zone was chosen and never replaces an offset the carrier states. Sparse fast answers must not suppress richer history. Separate parser tests, live retrieval, packaged service compatibility and deployed consumer behavior when assessing a fix.
- Installing a carrier's official app on an emulator, tracking a public number in it and capturing its traffic, through certificate pinning when the app pins, is a normal way to find an adapter's endpoints. Do it early rather than only when the website is blocked. Keep APKs, extracted bundles and raw live diagnostics outside Git. A shared credential that a carrier ships in its public app or gives every visitor of its public tracking page, the same for every install and used for guest tracking, may be included in that carrier's adapter so consumers need no credential setup; mark the line with `gitleaks:allow`. Account credentials, per-user or per-device tokens and sessions the adapter opens stay out of Git. Record endpoint leads and their access requirements in the carrier README; [DHL Express](carriers/dhl-express/README.md) includes the mobile and public browser flows. Project policy belongs here or in architecture documentation; reusable investigation methods belong in the reverse engineering skill.

## Documentation

Keep docs short, plain and current. No dates, verification logs, changelogs, one-off timings or hedging. Do not copy catalog, sample-number or status facts out of their machine-readable source. No status or field tables in READMEs.

Carrier and provider READMEs cover scope, retrieval, non-obvious choices with their reasons, limitations and the live-test command. Follow `npm run carrier:new`. Routing evidence belongs in `providers/COVERAGE.md` and measured coverage in `benchmark/`; adapter and facade policy in `ARCHITECTURE.md`. Generate README counts with `npm run generate` and update docs in the same commit as behavior. `npm run generate` leaves `data/detection-golden.json` alone: once a detection change is deliberate, rewrite it with `npm run generate:golden`. When a rule makes detection offer a carrier for a shared shape, `npm run generate:expectations -- <id>` adds it to the sample expectations and declarations it explains and lists the rest.
